## A. 残存事实 / 口径错误

### A1. Git worktree 定义仍把“独立分支”说成必然属性（中）
- 原文：Tree「**Git worktree**」卡片写「**独立目录 + 独立分支，通常建在工作区根下**」。
- 问题：独立工作目录是 worktree 的定义性特征；但它可以处于 detached HEAD，并不必然关联“独立分支”。“通常”修饰的是位置，不是分支，因此句子仍将分支写成必备条件。这也容易让读者把 Git worktree 和“新建一个分支”画等号。
- 建议：改为「独立工作目录；通常检出一个分支，也可处于 detached HEAD。worker 也可选当前或已有工作区。」

### A2. 主路第 5 步暗示 worker 一定在“自己的工作区”工作（中）
- 原文：Flow「**在自己的工作区里干：改 → 验证 → 报告**」。
- 问题：这与同一套说明中允许 `--worktree current` / 已有工作区的口径不完全一致：current 工作区并非 worker 独有。读者可能仍以为派 worker 会自动隔离文件目录。
- 建议：改成「在选定的工作区里干（可能是新建、已有或 current）：改 → 验证 → 报告」。

### A3. `--on` 被简化成“选执行机”，丢掉了 Orca server 这一层（低）
- 原文：Flow「**`--on` 只选执行机**」。
- 对照只读 CLI 原文：`--on selects only the worker server; the Run and this command remain on the current Orca server.`
- 问题：多服务器时，`--on` 选的是 worker server；Run 和发起命令仍在当前 Orca server。用“执行机”略过 server 边界，和本文正在解释的“机器/材料可达性”混在一起。并非说它派错机器，而是术语应精确。
- 建议：改成「`--on` 选择 worker 所在的 Orca server；Run 和发起命令仍在当前 Orca server。它不保证 worker 能读到另一台机器上的目录。」

## B. 结构与清晰度

### B1. 两图分工基本合理，但“全景关系”目前主要靠一条调度链表达
- 原文：Tree 标题「**四类东西 + 它们的关系**」；其中关系链是「**Run → Task → Dispatch → Worker → Agent**」，文件与场地、跟踪区则以并列卡片呈现。
- 判断：四组职责划分（身份对话、协调调度、文件场地、跟踪）清楚，术语表作为第五块辅助阅读也合理；“四类”不必改成五类。但读者看不出 Bot 怎样连接到 Worker、Repo/workspace 怎样连接到 Worker、Item/Automation 怎样参与流程。建议明确“箭头仅表示调度顺序”，并加最少量跨组关联线/标注，或直接把标题改成“四组概念与一条调度链”，避免承诺了完整关系图却只画一条链。

### B2. Flow 第 6 步把完成和三种异常塞进同一句，主路径/岔路边界不够直观
- 原文：「**完成、失败重试、waiting for human、需要授权，是四种不同的事，走下面三条岔路**」。
- 问题：完成其实是主路的正常结果；其余三种才分别对应失败、等待回答/授权、能力不符。读者要自行推断“下面三条岔路”不含完成。
- 建议：改成「成功完成后进入验收；若失败、等待人类回答/授权，或发现能力不符，分别走下面三条岔路。」

### B3. 非技术读者的第一眼可再减负
- 原文：Flow 顶部说明「**healthy but waiting for human**」，岔路含「**`--retry-of` 要配原 `--task`**」；Tree 则列出 Task 的六个英文状态。
- 问题：首屏同时出现较多英文状态、CLI 参数和内部术语。文档总体顺序（先全景、再流转）可读，但最好先给一句白话摘要/一个迷你例子，再把 CLI 细节放在“想深入时看”。这不是要求删掉证据，而是降低第一次阅读负担。

## C. 技术缺陷

**确认 2 项技术/可访问性缺陷（1 项布局风险，1 项表格语义）；未发现无 fallback 的主题变量、`vh` 禁忌或 Flow 标签错嵌。**

### C1. 窄屏有横向溢出的高风险（中）
- 原文 CSS：两份 `body` 都有「**padding:22px 24px 26px**」；Tree `.grp` 为「**grid-template-columns:150px 1fr**」，`.items` 的最小卡片宽「**minmax(190px,1fr)**」；Flow `.grid` 为「**minmax(240px,1fr)**」。Tree 表格另有 `td.b{...white-space:nowrap}`，Flow 有 `td.k{...white-space:nowrap}`。
- 问题：外边距、卡片内边距和不可压缩的网格最小宽度叠加；在 Orca 帧宽不固定且窄于桌面布局的情况下，至少网格或不换行单元格可能超出容器。源码没有媒体查询或表格横向滚动/换行兜底。静态推断，未实际截图，不应声称已观察到某尺寸的实测溢出。
- 建议：加窄屏 media query（缩小 body/card padding、Tree `.grp` 改单列、`.grid/.items` 允许 min-width:0），对长词设置 `overflow-wrap:anywhere`；表格可包一层 `overflow-x:auto`，或在窄屏转为块状条目。

### C2. 两个表格的列标题没有显式关联数据单元格（低）
- 原文：Tree、Flow 都是 `<table>` 内直接放 `<tr><th>…</th>`，没有 `<thead>` / `<tbody>`；所有 `<th>` 均无 `scope`。
- 问题：视觉上可读，但显式表头分组及 `scope="col"` 缺失，对屏幕阅读器的表格导航语义不够稳健。此项是可访问性缺陷，不影响普通视觉渲染。
- 建议：用 `<thead><tr><th scope="col">…`、`<tbody>` 包数据行；行标题（如“Run”“查一下、回一句、改一行”）若作为行标题，考虑 `<th scope="row">`。

### 已核对、无需修的技术点
- CSS 变量 fallback：76 处 `var()` 全都有逗号 fallback，例如 `var(--background,#fff)`、`var(--font-sans,system-ui,...)`。
- 未发现 `100vh` / `vh` 单位。
- Flow HTML 标签嵌套检查无错；Tree 协调段第二个 `<p>` 结束标签省略，但 HTML5 允许在后续块级 `<div>` 开始前省略 `</p>`，不算无效嵌套。
- 颜色主要使用 fallback 色值；仅凭源码不能确认 Orca 实际主题组合的最终对比度，因此主题色对比度列为未实测，不报为已确认问题。

## D. 本轮新增的增量建议（3 条）

1. **在两图之间加一个具体贯穿例子。** 例如“读一个本机文件 → 选择 worker → 检查文件可达 → 验收 → 清理”，对应 Flow「**依赖的本机条件**」和 Tree「**Folder 工作区**」，帮助读者把术语映射到真实操作，而不只记定义。
2. **把快照数值附上可复核出处。** Tree 原文「**Bot 5 个 · Repo 9 个 · automation 0 个（2026-11-26 核对，瞬时值）**」已提示会变；再标注查询命令/菜单路径，主人下次能自行更新，避免静态截图过期后看起来像事实错误。
3. **为颜色编码再加非颜色提示。** Flow 已有「**橙色=你，蓝色=bot，绿色=worker**」，建议保留颜色同时在节点/步骤上加角色字母或形状标识，让灰度打印、色觉差异或低对比主题下仍能识别责任人。
