主人让我第三遍自查。通读全文（不只看改过的地方），又查出 7 处，其中两处是「上一轮修复不完整」。

**① 修复不完整 A —— 同一个错误留在另一处**
上一轮把 ③ 卡片的「独立目录 + 独立分支」改成了「通常检出一个分支，也可 detached HEAD」，但 ⑤ 术语表的 Worktree 行还写着「新建的独立分支目录」。同一个错误，改了一处漏了另一处。已统一。

**② 修复不完整 B —— 上轮加澄清造成了重复**
上轮我把「不是每个 worker 都有终端」改成引用 CLI 原话 + 澄清，结果和下面「承载形态」那段重复讲了两遍终端，同一屏里说了两次同一件事。现在合并成一处：CLI 原话放进承载形态那段。

**③ 调度链把 Agent 画成了 Worker 的下游**
链是 Run → Task → Dispatch → Worker → Agent，箭头读起来像「Agent 是 Worker 之后的一环」。Agent 不是下一环，是「启动这个 Worker 的执行程序」。这正是 luna 批评我「Run→Task 顺序」时批评的同一类错误，我犯在自己身上。已改成链只 4 环，Agent 单独一句话说明。

**④ 「有两种承载形态」是过度断言**
luna 的原话是「结构化聊天 / 普通 terminal 等」，我写成「有两种」，等于把「等」删了。改成「至少有两种」。

**⑤ 数量词与实际不符**
flow 那张表标题写「看这四条」，表里实际 6 行。读者一眼能抓到的错。

**⑥ 步骤指针不准**
岔路 1 写「回主路第 3 步」，但失败重试既要重新确认可达性（第 3 步）也要重写 spec 再派（第 4 步）。改成「第 3–4 步」。

**⑦ 标题漏项**
