② 协调与调度 · 一条调度链（箭头只表示先后顺序，不是包含关系）

Run命名空间 + 收件箱，自己不调度也不挑机器→ Task要做的事：pending/ready/dispatched/completed/failed/blocked→ Dispatch一次派发记录（ctx_…）→ Worker受监督的执行实例，由某个 Agent 启动

注意 Worker ≠ Agent：Worker 是执行实例，Agent 是启动它的执行程序（pi / claude / codex / cursor / antigravity / muse / zcode / opencode / opencode2）。所谓「worker 分好几种」，其实是 Agent 类型不同，加上下条说的承载形态不同。

注意 worker 至少有两种承载形态：结构化（聊天）承载——不提供普通可交互的 terminal 窗格，在 Orca 里表现为一个聊天窗口（CLI 原话与判据见 ⑥ 第 3 行）；普通 terminal 承载——有可交互终端，也可用 --terminal 直接复用已有终端。准确说法就这一句：结构化承载没有可交互终端窗格。关掉它的承载会让那次 dispatch 失败（实例：lastError="Terminal closed by operator request"）。

派发参数 选执行程序之后，模型用 --model provider/id，深度用 --effort off/minimal/low/medium/high/xhigh/max（两个都不能与 --terminal 同用）。派到 current 或已有工作区时，不带 --name / --repo / --base-branch / --display-name / --comment / --setup——带了会被拒。

④ 跟踪 · 你只需要看这一层

Item 台账
跨回合跟踪。开着时是这几个状态之一：Planned（还没动）/ In progress（在干）/ Waiting（等外部）/ Needs you（等你决定）——不是一条必须按顺序走的流水线
Automation
按时间或事件触发一次后续；能监听什么取决于 trigger-options（很多要接 GitHub 等连接器）

口径 Item 开着时四态并列；Item 和 Automation 都是辅助跟踪手段，不是活着的必经层级，也不是开 worker 的前提。

用法 要等外部（CI / 别人评审 / 到点）→ 建 automation 等待 + 留 Item 记账，不要派一个 worker 在那儿轮流守着。

⑤ 术语一句话对照（读图前先扫一眼）

词一句话
Run命名空间 + 收件箱。自己不管调度、不挑机器；不绑 Run 时 worker-start 会自己建一个。
Task要做的事。状态：pending / ready / dispatched / completed / failed / blocked。
Dispatch一次派发的记录（ctx_…）。同一个 Task 可以重试多次、有好几个 dispatch。
Worker受监督的执行实例。按两条轴描述：执行程序（Agent）决定谁来执行，承载形态（结构化聊天 / 普通 terminal）决定怎么查看、交互和处置退出。不是每个 worker 都有可交互终端。
Agent启动 worker 用的执行程序类型：pi / claude / codex / cursor / antigravity / muse / zcode / opencode / opencode2。这是 such as 引出的开放列举，不是全部种类（见 ⑥）。
Worktree文件位置。--worktree 四值，其中 current 指当前工作区；四个取值与远程限制见 ⑥。
Item跨回合台账，给人看的进度和责任；不强制、不等于任务本身。
Automation到点或遇到事件时启动一次；能听什么取决于 trigger-options（很多要连接器）。
send --type给 worker / 别的 bot / Run 发信，共九种类型（不是三种）：handoff / question / status / worker_done / escalation / merge_ready / decision_gate / dispatch / heartbeat。含义与坑见 md「命令面」。
三种收场worker-stop 真停（关终端）/ worker-abandon 只隔离不碰进程 / worker-release 事后清理（幂等）。细节见流转图岔路一。

⑥ 已核对口径 · 说错就露怯（8 条 + 3 条硬限制）

结论依据 / 别再说成
Run 不管调度A Run is a namespace and home inbox. It never schedules or places workers.
Task 六个状态pending / ready / dispatched / completed / failed / blocked。注意 worker-show 里的 state 是 Dispatch 的态（ready / succeeded / failed / stopped），不是 Task 六态。
不能写「worker 没有终端」CLI 原话 Not every worker has a terminal = 没有可交互终端窗格。硬判据是 worker-read --source terminal 被拒（archive_unavailable: … has no terminal output）。结构化承载常见带 structworker_…，但不是通则，别拿字段存在当证据。
--agent 是开放列举CLI 原文是 such as，非穷尽；pi 不在那句名单里却实际在用。
--on 只选 server只选 worker 所在的 Orca server（Run 和发起命令仍在当前 server），不保证文件可达。
判断有没真读文件硬证据是 transcript 原话（worker-read --source transcript）；「引不出只有读过才知道的细节」是降级判据，不能反推「肯定没读」。
Item 状态不是流水线Planned / In progress / Waiting / Needs you 是并列的开着的状态，不按顺序派生。
bot 之间靠交接handoff 连责任一起交 / question 只请教、自己仍负责 / status 只同步。不按项目划死边界。

另外三条硬限制（不计入上面 8 条）：--worktree 四值 current / selector / new-child / new-top-level 且远程不能用 current（Remote current is invalid.）；--item 与 --on 互斥（It can't be combined with --on.）；stopReason=lost / liveness unverifiable 先别动——原 agent 可能仍在跑，既不授权发信也不授权重试。
